# Какие данные нужны от завода и в каком виде

Сервис принимает **Excel (.xlsx), Word (.docx) или CSV**. Названия колонок можно на русском или английском, порядок любой, лишние колонки не мешают: таблицы узнаются по смыслу заголовков. Загрузка: вкладка «Факты из ТЗ» → «Загрузить данные» → предпросмотр → «Применить». Двойник перекалибруется сам.

## Минимум (есть уже сейчас в ТЗ)

| Таблица | Обязательные колонки | Пример заголовков |
|---|---|---|
| Работа линий | дата, линия, план, факт | Дата / Date, Линия / Line, План / Plan, Факт / Actual, Время работы ч, Загрузка % |
| Качество | дата, участок, выпущено, брак | Дата, Участок, Выпущено / Produced, Брак / Defects |
| Простои | дата, участок, оборудование, причина, минуты | Дата, Участок, Оборудование / Equipment, Причина / Cause, Длительность мин |
| План по моделям | модель, план на месяц | Модель / Model, План на месяц |

Участки распознаются по словам: «свар…» → сварка, «окрас…» → окраска, «сбор…/конвейер» → сборка.

## Что сильнее всего улучшит точность (запрос к IT Allur)

1. **Номер смены** (shift_id) — сейчас не ясно, строка = смена или сутки.
2. **Точное время начала и конца остановок** + флаг «плановая / внеплановая».
3. **Идеальное время цикла по участкам** — без него OEE не вычисляется честно.
4. **Ёмкость буферов** между участками.
5. **VIN или номер кузова** в событиях — чтобы считать брак по машинам, а не по участкам.
6. **Классы дефектов окраски** — проверить гипотезу «фильтр → брак».
7. Поток событий из MES / PLC (OPC UA, MQTT) — для живого режима и самообучения на событиях, а не на суточных итогах.

## Поток событий (живой режим)

Камера контроля окраски и другие источники могут слать события по одному:

```
POST /api/learn/camera/event
{"event_type": "paint_defect" | "paint_ok", "asset_id": "paint.booth02", "body_id": "K12345", "defect_class": "подтёк", "source": "cv_camera"}
```

## Что меняется после загрузки реальных данных

- Факты и выводы строятся по новому файлу (с указанием источника каждого числа).
- Двойник подгоняет брак участков и темп линии под факт; на вкладке видно «двойник подогнан: N машин/смену при факте M».
- Оценка брака окраски в «Обучении» стартует от новых данных.
- Сравнение с TimesFM/Chronos нужно пересчитать: `backend/.venv/Scripts/python backend/scripts/tsfm_challengers.py`.
- Загруженные файлы хранятся локально в `data/uploads/` и **не попадают в git**.
