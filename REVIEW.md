# Для эксперта: как проверить Allur Flow за 5 минут

Кейс №2 Qostanai Industry Hackathon, АО «Группа компаний АЛЛЮР»: цифровой двойник автозавода.
Ролик 24 с: [`media/allur-flow-promo.mp4`](media/allur-flow-promo.mp4) · архитектура: [`ARCHITECTURE.md`](ARCHITECTURE.md) · сценарий демо: [`DEMO.md`](DEMO.md).

## Быстрый старт

```bash
./start.sh           # Linux/macOS (Windows: start.bat; или docker compose up -d --build) → http://localhost:8000
python verify.py     # 80 тестов + метрики против баз + реальная фабрика + results/*.json, *.csv
```
Нужны Python 3.12 и Node 20+. Тот же `verify.py`, сборка сайта и Docker-образа идут в CI на каждую загрузку (бейдж в README). Описание API: http://localhost:8000/docs.

ИИ-помощнику нужен ключ OpenRouter в `.env` (шаблон — `.env.example`). Без ключа он отвечает быстрыми ответами по тем же функциям двойника.

## Карта по критериям

### Полнота — выполнение задания, результаты JSON/CSV, аннотации, комплект поставки

| Требование ТЗ | Где в продукте | Где в коде |
|---|---|---|
| Визуализация участков и оборудования | «Двойник»: 3D, План, Схема — 6 участков, ABB-01/04, Камера-02, Конвейер-03 | `frontend/src/twin/`, `data/line.json` |
| Мониторинг: производительность, загрузка, простои, качество | Блок «Показатели ТЗ» на «Фактах» (данные Allur) и «Двойнике» (симуляция) | `frontend/src/KpiBoard.tsx`, `backend/app/sim/kpi.py` |
| Инциденты и отклонения | «Главные проблемы», журнал событий, нормы по дням, контрольная карта брака | `backend/app/findings.py`, `journal.py`, `spc.py` |
| Панель руководителя | «Брифинг» (сколько сделаем, что мешает, что сделать), журнал и прогноз месяца | `backend/app/briefing.py`, `journal.py` |
| Прогноз простоев и узких мест (ИИ) | Узкое место и шанс простоя > 60 мин на день; прогноз 2 ч (LightGBM) и риск провала; «что если» | `backend/app/sim/api.py`, `learn/` |
| Архитектура | Вкладка «Архитектура» (3D-слои, поток данных, цикл решения) + `ARCHITECTURE.md` | `frontend/src/arch/` |
| Демонстрация сценариев | `DEMO.md` (3 минуты), ролик | `promo/` |
| Оценка эффекта для бизнеса | «Эффект для завода»: машины, минуты простоя, OEE, ₸ в год, окупаемость | `backend/app/effect.py` |

**Результаты в JSON и CSV** — папка [`results/`](results/): нормализованные факты, выводы, KPI по участкам, прогноз смены и месяца, контрольная карта, эффект, брифинг, допущения. Пересобираются одной командой (`scripts/export_results.py`).

**Аннотации.** У каждого модуля есть описание назначения и метода в начале файла. У каждого числа есть метка источника (`fact` / `calc` / `assumption` / `sim` / `forecast` / `feedback`). Допущения перечислены явно (A1–A10, `results/assumptions.csv`).

**Комплект поставки.** Код (backend + frontend), тесты, `data/line.json` (описание линии), исходные материалы ТЗ (`data/raw/`), документация (`README`, `ARCHITECTURE`, `DEMO`, `DATA_FORMAT`, `docs/INTEGRATION.md`), Docker Compose + Caddy, PWA, ролик, результаты.

### Методы — пригодность алгоритмов, неопределённость, проверка качества, отсутствие подстановок

| Задача | Метод | Почему подходит |
|---|---|---|
| Поток линии, узкие места, «что если» | Дискретно-событийная симуляция (SimPy): накопители, отказы MTBF/MTTR, переделка окраски; узкое место — метод активных периодов | Стандарт для линий с буферами; сравнение действий на одинаковых случайных событиях (CRN), 95% интервал парной разницы |
| Брак против нормы | Байес (Beta, приор Джеффриса), p-карта Шухарта + правила Western Electric | Честно при малом числе дней; отделяет «шум» от особой причины |
| Прогноз выпуска 2 ч, риск провала | LightGBM на поправке к простому прогнозу; порог тревоги по цене ошибок (пропуск ×3), выбран на отдельных днях | Отложенные потоки эмулятора, новая версия — только если точнее на 3%; −34% ошибки против простого прогноза. Тот же метод на реальной фабрике: −6% к плану и −16% к «как вчера», обе разницы значимы |
| Коридор прогноза | Адаптивный конформный интервал (ACI) с конечной поправкой (n+1) — цель 90%, факт 90% на эмуляторе и 91% на реальной фабрике | Покрытие проверяется, а не обещается |
| Прогноз месяца | Монте-Карло: 40 вариантов параметров двойника × типичные дни | Учитывает, что двойник знает завод по 2 дням данных |
| Проверка эффекта действий (8D) | Односторонний тест долей, p < 0,01, минимум 5 дней, без дней с особой причиной | Защита от «возврата к среднему» |

**Неопределённость** показана везде: интервалы, шансы, коридоры; «данных мало» — так и написано.
**Проверка качества:** 80 тестов; проверка на реальной фабрике (UCI 597: ошибка 9,98 п.п. против 10,64 у плана, 95% ДИ разницы −1,25…−0,11; коридор 91% при цели 90%; провалы AUC 0,71) — раздел в README и `validation/real-factory/`; сбои данных 6 из 6 без ложных тревог; прогноз смены против данных Allur — в `results/RESULTS.md`. Тревога сравнивается со случайной с той же частотой, а не с долей провалов. Все числа пишет `verify.py` — в README они не вписаны вручную.
**Прогноз до факта:** утренний прогноз смены пишется в базу до её начала (таблица `forecasts` сама запрещает запись задним числом), запись дня помечает «записан заранее».
**Без подстановок:** дни 01–02.10 в журнале — из данных Allur (простои, брак, выпуск), а не выдуманные. План 5 500 против 4 800 подаётся как несогласованность плана, а не как недовыпуск. Замена фильтра — совпадение, а не причина. ИИ-помощник сверяет каждое число с расчётом.

### Технологичность — архитектура, воспроизводимость, тесты, ошибки, безопасность

- **Архитектура:** 6 слоёв (завод → приём → хранение → ядро → сервисы → экраны), один сервер отдаёт API и сайт; линия описана файлом. См. `ARCHITECTURE.md`.
- **Воспроизводимость:** точные версии зависимостей (`requirements.txt`, `package-lock.json`), фиксированные случайные зёрна, тесты на временной базе, `export_results.py` и `promo/` пересобирают результаты и ролик.
- **Тесты:** `backend/tests/` — 80 тестов (данные ТЗ, симуляция, обучение, журнал, качество, эффект, ИИ-помощник, раздача сайта, защита). CI: тесты + метрики, сборка сайта, сборка и запуск Docker-образа.
- **Обработка ошибок:** загрузка файлов не падает на непонятных строках (предупреждения); прогрев при старте не роняет сервер; офлайн-режим PWA; ИИ — запасные модели и быстрые ответы без сети.
- **Безопасность:** ключи только в `.env` (в git не попадают); публичный запуск без PIN администратора запрещён; изменения под PIN (`hmac.compare_digest`), лимит вопросов к ИИ; загрузка читается кусками и обрывается на 20 МБ (и в Caddy); входные данные проверяются Pydantic; SQL — только параметризованные запросы; контейнер не от root. ## Честно об ограничениях

Полная сверка с ТЗ: [`spec-compliance/REPORT.md`](spec-compliance/REPORT.md) и [`ADDENDUM-claude.md`](spec-compliance/ADDENDUM-claude.md).
- Данных заказчика — 2 дня; остальная история и обучение моделей — на эмуляторе завода (подписано «симуляция»).
- Живые события с линии принимаются и показываются, но в расчёты двойника пока не идут — первый шаг пилота.
- Казахский — интерфейс главных экранов; выводы сервера и ответы ИИ пока на русском.
- Эффект в деньгах держится на допущении маржи A8; разбор и чувствительность (82–241 млн ₸/год) — в README.
