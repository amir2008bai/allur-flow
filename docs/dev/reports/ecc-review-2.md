# Allur Flow — второй разбор по скиллам ECC: дыры, точность прогноза, новые функции

Дата: 8 октября 2026. ECC (github.com/affaan-m/ECC, 293 скилла) скачан заново и прочитан как чек-листы, без установки.
Использованы новые для нас скиллы: `production-scheduling` (теория ограничений, DBR, OEE, реакция на сбои),
`quality-nonconformance` (SPC, 8D/CAPA, IATF 16949 — стандарт качества автопрома), `mle-workflow` (цена ошибок модели,
неопределённость, анализ ошибок). Всё сверено с ТЗ (`data/raw/case_brief.pdf`) и тестовыми данными (`data/raw/test_data.docx`).

## 2. Точность прогнозов — эксперимент

Добавили в LightGBM признаки «какой участок стоит сейчас», «сколько ему ещё чиниться (по MTTR)», «как меняются буферы»,
«сколько до конца смены». 300 обучающих потоков, проверка на 10 отложенных потоках и 40 новых случайных днях:

| | Ошибка выпуска за 2 ч (машин) | Простой прогноз | AUC провалов |
|---|---|---|---|
| Сейчас | 2,66 / 2,73 | 4,03 / 4,18 | 0,62 / 0,71 |
| С новыми признаками | 2,63 / 2,72 | — | 0,62 / 0,71 |

**Вывод (честно): новые признаки почти ничего не дают — не внедряем.** Провалы в основном вызывают будущие внезапные
поломки, которых по текущему состоянию линии не видно. Реальный рычаг — данные завода (микроостановки, ошибки датчиков,
вибрация перед отказом) и правильный порог тревоги (Н3). Модель уже на 34–35% точнее простого прогноза.

## 3. Новые функции — полезные именно для автозавода

| Идея | Что видит начальник смены | Откуда | Ценность | Трудоёмкость |
|---|---|---|---|---|
| **Контрольная карта брака окраски** (карта Шухарта + правила Western Electric) | Брак по сменам с границами «обычный разброс»; сигнал «особая причина — разбираться» или «шум — не трогать процесс» | SPC, стандарт автопрома IATF 16949 | Высокая: главный сценарий — брак окраски; инженеры качества Allur знают этот инструмент | Малая |
| **Цена минуты простоя по участкам** | «Минута простоя окраски стоит X ₸, сварки — меньше (её прикрывает буфер)» (числа посчитает двойник) → какой ремонт первым | ТОС: минута узкого места = минута всего завода | Высокая: решение для службы ремонта; уникально | Малая (двойник уже умеет) |
| **Проверка узкого места «+1 час»** | «Дать участку +1 час → +N машин» для каждого участка; узкое место там, где N больше | ТОС: «если добавить час — вырастет ли выпуск?» | Высокая: доказательство, а не догадка | Малая |
| **Защита узкого места буфером** (зелёный/жёлтый/красный) | Буфер перед узким местом: зелёный — спокойно, жёлтый — ускорить подачу, красный — срочно | DBR (барабан-буфер-верёвка) | Средняя–высокая | Средняя |
| **Каскад потерь OEE** | План 240 → − авария → − брак → − ожидание кузова → факт (пример формы, числа из двойника) | OEE (из прошлого разбора) | Высокая | Средняя |
| **Карточка 8D для брака** | Проблема → сдерживание → причина (5 почему) → действие → проверка эффекта через N смен (двойник сам сверяет) | 8D/CAPA, автопром | Средняя–высокая: замыкает «учится» | Средняя |
| **Правила эскалации** | «Узкое место стоит > 30 мин → начальник производства», «брак > 2% три смены → инженер качества» | `production-scheduling` | Средняя (с Telegram — высокая) | Малая |
| Выравнивание моделей (хейдзунка) | Последовательность Onix/Cobalt/JAC 5:4:1 в смене | JIT | Низкая: нет данных о циклах моделей — много допущений | Средняя |

## 4. Рекомендация (порядок)

1. **Н1** — журнал 01–02.10 по фактам заказчика (обязательно до показа).
2. **Н2 + Н3** — честная формулировка самопроверки, порог тревоги провала по цене ошибки.
3. **Контрольная карта брака окраски** + **цена минуты простоя / «+1 час»** — дёшево, узнаваемо для производственников, уникально.
4. Каскад потерь OEE (Н5) и карточка 8D — если хватит времени.
